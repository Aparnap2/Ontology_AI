# Agent Evaluation — OntologyAI

Branch `feature/ontologyai-onboarding-restructure` · HEAD `cd7fe05`

**This document is deliberately separate from the regression gate.** Model-quality
evaluation is not a security test and must never be run inside the code-change
loop.

---

## 1. The split

| Gate | Command | Needs credentials | Failure means |
|---|---|---|---|
| Deterministic regression | `pytest -m "not llm"` | no | **a defect** |
| Live-model evaluation | `pytest -m llm` | yes | **a quality signal, not necessarily a defect** |

The split is static and declared per-file (`pyproject.toml:80-88`), not derived
from whether a credential happens to be present. A suite cannot silently flip
between "regression" and "evaluation" depending on the environment.

### Why this split exists

`tests/test_agentic_capability.py` made 40 real provider calls and failed with
`openai.AuthenticationError: 401 Invalid API Key`. That is not a security finding.
It means the *deterministic* gate was silently coupled to a credential.

**A control-plane boundary that can only be tested when an API key happens to be
valid is not a boundary that can be relied upon.**

The 40 failures were Category **C** (environment), not defects. They are now
behind `-m llm` (`tests/test_agentic_capability.py:38`) and are excluded from the
regression count by declaration, not by suppression.

## 2. What each tier can and cannot establish

| Tier | Proves | Cannot prove |
|---|---|---|
| Deterministic control-plane tests | Authority, policy, idempotency, audit, verification semantics under attack | Model quality, semantic correctness of a decision, anything requiring a live model |
| Model-quality evaluation (`-m llm`) | Whether the model produces acceptable output on a given corpus | Security boundaries — an evaluation run proves nothing about the control plane |
| Real-worker Temporal tests | Delivery, persistence, retry, restart | Model quality |

Never merge the three. A suite that claims to cover two tiers proves neither.

## 3. Evaluation tiers present in the repository

| Tier | Location | Kind | Deterministic? |
|---|---|---|---|
| Golden trajectories | `tests/deterministic/test_trajectory_verification.py` (287 collected in `tests/deterministic/`) | Connector order, alert assembly, correlation, state assembly | yes |
| Behavioural contracts | `tests/deterministic/test_behavioral_contracts.py` | Domain state invariants (construction never raises, enums always valid, defaults always defined) | yes |
| State-machine transitions | `tests/deterministic/test_state_machine_transitions.py` | Legal/illegal transitions | yes |
| Edge cases | `tests/deterministic/test_edge_cases.py` | Boundary inputs | yes |
| deepeval metrics | `tests/test_deepeval_evals.py`, `.deepeval/run_evals.py` | Classification correctness, severity accuracy, spec quality, duplicate detection | **no** — needs a model |
| DSPy evals | `tests/test_dspy_evals.py` | Prompt/program optimisation | **no** |
| Live LLM integration | `tests/integration/test_real_llm_integration.py:16` | Real provider round-trip | **no** |

Golden trajectories are the highest-value deterministic tier here: they assert
*what the system does with data it already has*, with no model in the path.

## 4. Evaluation standard

| # | Rule | Why |
|---|---|---|
| 4.1 | An evaluation result never gates a security claim | Model quality and authority are orthogonal; a model that answers well still has no authority (`policy.py:41-48`) |
| 4.2 | An evaluation suite must declare `-m llm` at module level | A credential-dependent suite that forgets the marker becomes a Category C failure in the deterministic gate |
| 4.3 | Evaluation corpora are data, not generated at test time | `pyproject.toml:87` lists `llm`, `e2e`, `integration` as the only markers; a corpus generated by the model under test is not a measurement |
| 4.4 | Evaluation is never run in the code-change loop | Per Section 1 |
| 4.5 | A regression suite that starts needing a model is a **regression in the test**, not a new requirement | Reclassify it `-m llm` and find a deterministic substitute, or accept that the boundary is untestable |

## 5. Agent-behaviour evaluation — what is and is not measured

| Behaviour | Measured? | Evidence |
|---|---|---|
| Tool/op selection is inside the allowlist | **yes, deterministically** | `tests/test_p0_capability_allowlist.py` (8) |
| Risk tier cannot be set by the agent | **yes, deterministically** | `tests/test_p0_policy_trust_boundary.py` (13) |
| A composed prompt-injection attack is rejected end to end | **yes, deterministically** | `tests/test_p0_composed_attack_regression.py` (10) |
| Recovery claims carry evidence | **yes, deterministically** | `tests/test_p0_no_misleading_claims.py` (18) |
| Connector event ordering under duplicate/out-of-order/malformed input | **yes, deterministically** | `tests/test_failure_injection.py` |
| Business-decision *quality* (is this the right action?) | **only via `-m llm`** | `tests/test_agentic_capability.py` etc. |
| Semantic correctness of a governed write | **no** | `verify.py:88-104` derives expectations from the write — transport fidelity only |

That last row is the significant one. A read-back that passes does not mean the
action was *right*. It means the bytes round-tripped. The label
`expectation_source="derived_from_write"` (`verify.py:57-59`) makes this visible
in the data; it does not change the underlying limit.

## 6. Running evaluation

Separate terminal, separate concern, separate concern from the regression gate.

```bash
cd apps/ai

# Requires live provider credentials. NOT part of the release gate.
.venv/bin/python -m pytest -m llm -v

# deepeval corpus
.venv/bin/python -m pytest tests/test_deepeval_evals.py -v

# DSPy
.venv/bin/python -m pytest tests/test_dspy_evals.py -v
```

Rate-limit budget for any evaluation run: cap real calls, log the raw response on
failure, and stop. A retry loop against a rate-limited provider produces no
additional signal.
